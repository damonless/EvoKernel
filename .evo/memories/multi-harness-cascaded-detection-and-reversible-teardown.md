## Symptom
Issue #9-#17 multi-harness & release defects: Windows .cmd proxy EBUSY test races, external repo CLI/MCP path resolution, Claude Code nested hooks, evo virtualize --restore leaving auto-injected evo-kernel entries or skipping quoted TOML server keys ([mcp_servers."github.enterprise"]), and .github/workflows/publish.yml YAML syntax failure on unquoted colon-space in step name.

## Root Cause
1) External repo initialization hardcoded ./scripts/boot-mcp.mjs, Claude hooks lacked nested matcher arrays, and Windows MCP proxy shims needed .cmd resolution without in-place .cmd test overwrites (EBUSY); 2) runVirtualize auto-injected evo-kernel into host configs without recording injectedEvoKernel, leaving evo-kernel behind on --restore, while parseCodexTomlMcpServers missed quoted TOML server names ([mcp_servers."my.server"]); 3) .github/workflows/publish.yml had an unquoted ': ' inside a YAML step name, causing GitHub Actions YAML parse failure prior to job creation.

## Solution
1) Add resolveInstalledEvoKernelRoot/resolveEvoMcpLaunchConfig, Claude PostToolUse/Stop nested matcher hooks, Windows .cmd resolution + roots/list handshake, and separate probe/live .cmd test shims in mcp-proxy.test.ts; 2) Track injectedEvoKernel on VirtualizedServerOrigin so evo virtualize --restore removes auto-injected evo-kernel blocks while preserving pre-existing entries, and parse/format quoted TOML keys via parseCodexMcpHeader / formatCodexTomlKey; 3) Quote YAML step names containing colons and pass NPM_DIST_TAG via env in .github/workflows/publish.yml.
