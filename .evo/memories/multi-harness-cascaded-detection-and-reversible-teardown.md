## Symptom
Issue #9 Red-Team Audit, Windows/roots MCP proxy handshakes, external repo CLI/MCP path resolution, Claude Code official PostToolUse/Stop nested hook schema, and one-click third-party MCP virtualization (evo virtualize).

## Root Cause
1) Issue #9 Round 3/4 + Retrospective proxy gaps: handleRun resolved cachedExtTool before awaiting ensureExternalToolsSynced, Windows spawn lacked .cmd/.bat PATH resolution, and MCP initialize omitted roots capability/rootUri; 2) External repo initialization hardcoded ./scripts/boot-mcp.mjs even when run outside EvoKernel's repo, and upsertClaudeSettings wrote flat post-tool/stop strings instead of Claude Code's official PostToolUse/Stop nested matcher-hooks arrays; 3) Users with multiple third-party stdio MCPs suffered 5,000-15,000 tokens of Always-On schema bloat without a one-click folding/restore CLI command.

## Solution
1) Resolve .cmd/.bat/.exe paths via resolveWindowsSpawnCommand, advertise roots capability + rootUri in McpClientConnection.connect(), and support both ext__<server>__<tool> and mcp:<server>:<tool>; 2) Add resolveInstalledEvoKernelRoot, resolveEvoMcpLaunchConfig, and resolveEvoHookCommand in src/cli/harness.ts for external repositories, forward hook subcommands in scripts/boot-mcp.mjs, and emit Claude Code's official PostToolUse and Stop nested matcher-hooks structure in upsertClaudeSettings; 3) Add evo virtualize (--dry-run, --restore) in src/cli/virtualize.ts to fold third-party stdio MCPs from host configs into .evo/mcp-pool.json and .evo/config.json (externalServers) with lossless restoration.
